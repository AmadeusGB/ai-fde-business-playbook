# 阅读说明

本书面向企业经营者与技术团队。经营者可据此选择人工智能（AI）项目、安排投入与责任、核验经营结果；技术团队可把业务目标落实为流程、权限、评测和接管要求。参与项目的业务、财务和采购人员，也可用本书核对交付承诺。

书中多次提到FDE，即Forward Deployed Engineer，本书译为“前线部署工程师”。这类工程人员直接面对业务使用者，参与构建、修改和交付系统。他们的工作是把技术带进业务现场；经营决策、业务审批和结果确认，仍需由企业中有相应职责的人承担。第2章介绍这一角色的来历，第3章说明它与软件智能体、数字岗位的区别。

全书分为五部，共十八章，依次讨论如何看懂问题、作出投入决定、完成交付、判断经营结果，以及建立持续落地的组织能力。第一次阅读，建议按顺序推进；带着具体问题查阅时，可以从目录中的相应章节进入。

贯穿全书的判断是：每次增加投入或扩大使用，都应说清要完成的工作、支持决定的证据，以及接收结果的人。条件改变后，原来的决定也要能够复查和修正。第1章提出问题，第18章将这套判断落实到首轮项目的排期和决定单。

如果正在准备第一个项目，可以先读第1章和第18章，再按下表查阅。六步对应十张主表，先填写当前决定需要的内容，详细记录可引用企业已有材料。

| 当前要作的决定 | 查阅章节 | 先用的工具 |
|---|---|---|
| 选什么任务，允许投入多少 | 第4—5章 | 04-1选题与访谈；05-1投入、基线与继续条件 |
| 谁批准、执行和接收 | 第6章 | 06-1责任与接手 |
| 实际工作怎样完成 | 第8章 | 08-1现场观察与流程回放 |
| 允许系统做什么，凭什么放行 | 第9—10章 | 09-1资料治理；09-2动作治理；10-1准入 |
| 员工是否用起来，结果是否成立 | 第11—12章 | 11-1采用记录；12-1经营结果核验 |
| 下一阶段继续、调整还是结束 | 第18章 | 18-1下一阶段决定 |

外购服务时加读第7章；出现失败或考虑退出时查第13章。第14—17章分别处理成果复用、服务收支、多方交付和经验规则的维护。需要辨认招聘或采购对象时，回到第2—3章。第15章的项目、人手配置与续约账主要供经营交付业务的人复算；买方可重点查收费范围、持续支持和替换负担。

阅读案例时，请留意数字所对应的任务、时间和条件。真实案例、教学算例和作者提出的分析框架均有标注。计划中的目标、演示中的表现和实际运行结果，不能当作同一种证据。正文中的“实施要点”和“经营与财务”侧栏，分别补充交付细节与经营判断。

相近的教学场景不一定共用一套数字。例如，第4—10章多次使用结算任务，分别演示选题、预算、合同、观察、设计和准入；第5章的6.6万元现金预算与第7章的10万元服务包是独立设定，不能相加。第12章的月度结果账也不承接这两笔投入。第14章的维修受理、第16章的巡检、第17章的付款例外与第18章的备件询价各有用途，阅读时按本章记录理解。实际项目则应使用同一任务编号连接自己的记录。

书后收录十八份行动工具，可结合各章使用。填写前，先明确要处理的任务、责任人和观察范围；尚无依据的项目可以保留空白或写明“未知”，再安排补充记录。工具的作用是帮助团队形成共同判断，不能代替实际执行与核验。
